# Proactivity Assistant

*README prose word count: UPDATE AT THE END*

A prototype coding assistant that lowers its level of proactivity when the user seems to over-rely on it. It starts by suggesting full fixes; after several fixes are accepted without changes it switches to only pointing out where a problem might be, and it switches back once the user is checking suggestions again.

## Project status
- **Working:** 8 coding tasks, each with an assistant fix the user can use, edit or reject.
- **Working:** two levels of proactivity: **Suggest** (full fix shown) and **Notify** (only the line with a possible issue, fix shown on request).
- **Working:** adaptation rule with hysteresis: 3 unedited accepts in a row → Notify; 2 edits or rejections in a row → back to Suggest.
- **Working:** mode banner with the reason for each change, a manual override button, and an interaction log that flags wrong fixes accepted without changes.
- **Simulated:** the assistant's fixes are pre-written in `tasks.py`, not generated by a live model. Three are deliberately wrong so over-reliance can be observed.
- **Not built (planned):** live LLM suggestions, integration with a real code editor, response time as an extra over-reliance signal, saving logs between sessions, a user study.

## Technology stack
- **Python 3** for the application logic.
- **Streamlit** for the interface (buttons, text areas, mode banner). Chosen because it gives an interactive web page from a short Python script.
- **Git / GitHub** for version control.
- **No AI model is used at runtime.** Suggestions are simulated so the adaptation behaviour can be tested with known right and wrong fixes. A live LLM is a planned replacement for `tasks.py`.

## Running the work
```
git clone https://github.com/tsoisa/proactivity-assistant.git
cd proactivity-assistant
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
The app opens in a browser. To see the adaptation: use the first 3 fixes without changing them (switches to Notify), then edit or reject 2 fixes (switches back to Suggest). Open **Interaction log** at the bottom to see every action. Refresh the page to start again. No API key is needed.

**Observations from test runs** (used in the report):
- Two fixes were accepted about one second apart, including a wrong one, which suggests response time could be a further signal.
- No wrong fix was accepted in Notify mode.
- A wrong fix was accepted straight after the assistant returned to Suggest.
- Rejecting a correct fix counts as "engaged", so the system cannot tell careful checking from simply saying no.
