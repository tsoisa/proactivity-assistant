# Proactivity Assistant

*README prose word count: ~___*

A prototype coding assistant that lowers its proactivity when the user accepts its fixes without checking them. It starts by showing full fixes. After 3 fixes are accepted without changes, it only points to the line where the problem might be. Once the user starts checking again, full fixes come back.

## Project status
- **Working:** 8 short coding tasks. For each one you can use, edit or reject the assistant's fix.
- **Working:** two levels of proactivity: **Suggest** (full fix shown) and **Notify** (only the problem line with the fix shown on request)
- **Working:** 3 unedited accepts in a row → Notify; 2 edits or rejections in a row → back to Suggest.
- **Working:** mode banner with the reason for each change, a manual override switch, an interaction log that flags wrong fixes accepted without changes and end screen count.
- **Simulated:** fixes are pre-written in `tasks.py`, not generated by a live model. Three are deliberately wrong so over-reliance can be measured.
- **Planned:** live AI fixes, a code editor plug-in, response time as an extra over-reliance signal, saving logs between sessions, a user study.

## Technology stack
- **Python 3** for the application logic.
- **Streamlit** for the interface. I chose it because it turns a short Python script into an interactive web page, and I'm most comfortable with Python.
- **Git / GitHub** for version control.
- **No AI model is used at runtime.** A live model is a planned replacement for `tasks.py`.

## Running the work
```
git clone https://github.com/tsoisa/proactivity-assistant.git
cd proactivity-assistant
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py

```

The app opens in a browser. To see the adaptation: click 'use this code' on the first 3 fixes without changing them. It switches to Notify, then click 'Show me the fix' and 'edit' or 'reject 2 fixes'. It then switches back to Suggest . Open **Interaction log** at the bottom to see every action. Refresh the page to start again. No API key is needed.

**Observations from test runs** (used in the report):
- I accepted two fixes within about a second, and one of them was wrong, so response time could be another useful signal
- In a later run, I revealed and then accepted two wrong fixes in Notify mode within 2–3 seconds, so Notify alone doesn't stop over-reliance if the user doesn't actually check the fix.
- A wrong fix was accepted straight after the assistant returned to Suggest.
- Rejecting a correct fix counts as "engaged", so the system cannot tell careful checking from simply saying no.
